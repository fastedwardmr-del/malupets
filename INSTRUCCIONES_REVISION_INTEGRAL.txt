HALLAZGO PRINCIPAL
------------------
Tus datos NO fueron borrados.

El problema que hace que después del login parezca que Productos,
Ventas, Clientes o Mascotas están vacíos es la capa nueva de permisos.

El frontend ya reconoce ADMIN como acceso total, pero el middleware del
Worker dependía todavía del campo "permissions". Si ese campo quedó con
un formato de una versión anterior o mal serializado, el Worker devolvía
403 en /api/products, /api/sales, /api/customers, etc.

Las pantallas interpretaban esas respuestas como si fueran listas vacías.

CORRECCIONES DEL PAQUETE
------------------------
1. ADMIN tiene acceso total también en el BACKEND.
2. Se aceptan permisos tanto como JSON válido como formatos heredados.
3. Login normaliza el rol a mayúsculas.
4. PBKDF2 queda en 100000 iteraciones en auth.js Y users.js.
   Antes users.js seguía en 120000 y crear/cambiar contraseñas iba a fallar.
5. app.js devuelve errores HTTP correctamente en lugar de disfrazarlos
   como datasets vacíos.
6. Compatible con URLs limpias (/pos) y archivos (/pos.html).
7. No se toca D1.
8. No se toca R2.
9. No se reemplazan POS, inventario, ventas, clientes ni mascotas.
   Se preservan las versiones funcionales que ya tienes.
